# Terraform infrastructure

Infrastructure as code for the secrets rotation platform. Composition is
**per-environment** so dev and prod stay isolated with separate state and
permissions.

```
terraform/
├── modules/
│   ├── network/           # VPC, public + private subnets, single NAT gateway, S3 gateway endpoint
│   ├── secrets-manager/   # master + database + API secrets, metadata & tags
│   ├── iam/               # least-privilege rotation Lambda role
│   ├── rotation-lambda/   # packaged rotation function + invoke permission
│   ├── monitoring/        # log group, error metric filter, alarms
│   ├── database/          # private, non-public RDS PostgreSQL
│   ├── cicd-identity/     # GitHub Actions OIDC provider + scoped deploy role
│   ├── eks/               # EKS cluster + node group + OIDC provider + KMS envelope encryption
│   └── eks-irsa/          # read-only IRSA role (dev-myapp-eso-reader) for External Secrets Operator
└── environments/
    ├── network/           # BOOTSTRAP: apply first; VPC + subnets + NAT gateway
    ├── cicd/              # BOOTSTRAP (one time): GitHub OIDC provider + scoped CI deploy role
    ├── dev/               # the app: secrets, Lambda, RDS, monitoring
    └── eks/               # EKS + External Secrets Operator (own state; reads network outputs)
```

## Two-layer workflow

Apply the **network** layer first, then the **dev** app layer. They have
separate state so the network has an independent lifecycle (destroying the app
does not tear down the VPC). The dev layer reads the network layer's outputs
automatically.

```powershell
# 0. Build the Lambda package (vendors psycopg for the Lambda platform):
python ..\..\scripts\build_lambda.py

# 1. Network layer — from terraform/environments/network
terraform init
terraform apply        # creates VPC, public + private subnets, NAT gateway, S3 gateway endpoint

# 2. App layer — from terraform/environments/dev
terraform init
terraform plan -out tfplan   # review; NOTHING is created until apply
terraform apply tfplan       # review costs first (../../docs/costs.md)
```

Already have a VPC? Skip the network layer: set `use_network_remote_state =
false` in the dev tfvars and supply `vpc_id` / `private_subnet_ids`.

For a free validation pass without any AWS calls or credentials:

```powershell
terraform init -backend=false
terraform validate
```

## Safety

- **No secret values in config, outputs, or tags.** Initial passwords are
  generated by `random_password` at apply time; the secret value is then owned
  by rotation (`ignore_changes = [secret_string]`).
- **State contains sensitive material** (the generated bootstrap passwords).
  Use the encrypted S3 backend with a DynamoDB lock table and restricted
  access. See `../../docs/terraform-state.md`.
- **Private RDS.** `create_database = true` provisions a non-public RDS instance
  the rotation Lambda reaches over a security group it alone can use; the
  secret's `db_host` is wired from the RDS endpoint automatically. Set it false
  only to deploy the secrets/Lambda/monitoring layer against an existing
  database. The database is never publicly accessible.

## Verified

`terraform fmt -check -recursive` passes against the configuration. `terraform
init` + `validate` run in CI (and locally once the AWS provider plugin loads).
Provider pins resolve to AWS 6.x / archive 2.x / random 3.x (current stable).
`terraform apply` requires AWS credentials and creates chargeable resources —
see `../../docs/costs.md`.
